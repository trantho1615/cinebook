# Milestone 6 — worker

**Goal:** Deployable thứ hai chạy được: sweeper dọn ghế hết hạn, outbox relay đẩy event lên Kafka thật, consumer gửi thông báo idempotent, và ghế đổi màu realtime trên UI. Sau milestone này, **worker chết thì hệ thống vẫn bán được vé** — và điều đó được chứng minh bằng test, không phải bằng lời.

**Architecture:** `cinebook-worker` **không chứa logic nghiệp vụ**. Nó là một runtime: phụ thuộc `cinebook-api` như một thư viện, kích hoạt đúng những use-case cần chạy nền bằng một danh sách `@Import` tường minh, rồi bọc chúng trong `@Scheduled` và `@KafkaListener`. Business code vẫn nằm nguyên trong module của nó ở `cinebook-api`.

**Tech Stack:** Spring Boot 4.1.0, ShedLock 7.9.0, Kafka 4.3.1 (`spring-boot-starter-kafka`), Redis pub/sub, STOMP over WebSocket, Testcontainers 2.0.5, Awaitility 4.3.0.

**Spec:** `docs/specs/2026-08-11-cinebook-core-design.md` — phủ mục 2.1 (hai deployable), 6.5 (relay), 6.6 (hai lớp hết hạn), 6.7 (realtime), và bốn dòng cuối bảng sự cố mục 7 (Redis chết, Kafka chết, worker chết, relay gửi trùng).

## Global Constraints

Kế thừa toàn bộ ràng buộc của Milestone 1-5. Nhắc lại những điều áp dụng trực tiếp:

- **Java 25**, **Spring Boot 4.1.0**, base package `com.cinebook`.
- **Jackson 3.1.4** — `JsonNode` và `ObjectMapper` ở `tools.jackson.databind`.
- **Chạy nhiều test cùng lúc dùng dấu phẩy**: `-Dtest=A,B`. Luôn đọc con số `Tests run:`, không đọc chữ `BUILD SUCCESS`.
- **Ranh giới module:** `ModuleBoundaryTest` vẫn cai trị. Module chỉ được import `<module>.api` của module khác. Đã bắt lỗi trong plan của tôi 4 lần qua 5 milestone — giả định rằng nó sẽ bắt lần thứ 5.
- **Đường ghi dùng `NamedParameterJdbcTemplate`**, không dùng JPA.
- **Thời gian lưu `timestamptz`**, ứng dụng dùng `Instant`.
- **Commit message không dấu**, Conventional Commits, không trailer đồng tác giả, không nhắc công cụ AI.
- **Mỗi task một commit**, `mvn -B verify` xanh trước khi commit.
- **Migration chỉ thêm, không sửa file cũ.** V13, V14 là số tiếp theo.
- **`cinebook-worker` không được khai báo endpoint HTTP nghiệp vụ** — `WorkerApplicationTest.worker_khong_khai_bao_endpoint_http_nghiep_vu` đã canh sẵn từ Milestone 1.

## Bằng chứng đã thu thập trước khi viết plan

Toàn bộ kiến trúc của milestone này đứng trên câu hỏi "worker lấy code nghiệp vụ ở đâu". Đã kiểm chứng bằng thực nghiệm trước khi viết một dòng plan nào:

## Quyết định thiết kế cần hiểu trước khi code

**Worker là runtime, không phải nơi ở của code.** Nếu worker tự viết SQL sweeper/relay/đối soát thì sau ba lần sửa, hai bản sẽ lệch nhau và không ai biết bản nào đúng. Worker phụ thuộc `cinebook-api`, và kích hoạt bean bằng một danh sách `@Import` **tường minh** trong `WorkerBeans.java`. Danh sách đó chính là câu trả lời cho "worker chạy những gì" — đọc một file là biết.

**Vì sao `@Import` tường minh mà không `@ComponentScan("com.cinebook")`.** Quét cả `com.cinebook` sẽ kéo theo controller, `SecurityConfig`, filter JWT và toàn bộ chuỗi phụ thuộc của chúng vào một tiến trình không phục vụ HTTP request nào. Nó cũng làm rỗng nghĩa của `WorkerApplicationTest.worker_khong_khai_bao_endpoint_http_nghiep_vu`. Liệt kê 9 bean tốn 9 dòng và mua lại quyền kiểm soát hoàn toàn.

**`application.yml` của api bị bỏ qua — và đó là điều tốt.** Worker khai báo cấu hình của riêng nó. Bean nào cần property mà worker quên khai thì context **chết ngay lúc khởi động** với lỗi placeholder, không phải chạy sai âm thầm. Task 1 có một test khoá hành vi này lại để người sau không mất một buổi chiều đi tìm.

**Ai sở hữu schema.** `cinebook-api` chạy Flyway; worker đặt `spring.flyway.enabled: false`. Hai deployable cùng migrate là cách chắc chắn có ngày một bản deploy nửa vời làm hỏng schema. Test của worker bật lại Flyway qua `@TestPropertySource` vì container test là DB trắng.

**Sweeper KHÔNG chịu trách nhiệm về tính đúng đắn.** Lazy expiration ở `HoldSeatsUseCase` mới là thứ đảm bảo không ai bị khoá ghế oan. Sweeper chỉ mua **tính kịp thời**: UI người khác thấy ghế trống ra mà không cần ai thử giữ. Test phải chứng minh điều này bằng cách tắt sweeper và khẳng định vẫn giữ được ghế đã hết hạn của người khác.

**ShedLock cho sweeper và đối soát, KHÔNG cho relay.** Relay đã có `FOR UPDATE SKIP LOCKED` — nhiều instance chạy song song là *tính năng*, mỗi instance nhận một tập dòng rời nhau (đã kiểm chứng ở Milestone 5). Bọc ShedLock lên relay là tự tay biến một thiết kế scale ngang thành một thiết kế một-instance. Sweeper thì ngược lại: hai instance cùng chạy sẽ cùng phát event `BookingExpired` cho cùng một đơn.

**`usingDbTime()` cho ShedLock.** Không có nó, ShedLock so giờ bằng đồng hồ của máy ứng dụng. Hai máy lệch nhau vài giây là đủ để hai instance cùng tin rằng lock đã hết hạn. Dùng giờ của DB thì chỉ có một đồng hồ.

**Event trên Kafka phải mang id của dòng outbox.** Giao hàng là at-least-once, nên consumer buộc phải khử trùng. Thứ khử trùng theo phải là một id ổn định do bên gửi sinh ra — `outbox_events.id`. Payload nghiệp vụ hiện tại (`{"bookingId":...}`) không có nó, nên Task 3 đổi chữ ký `EventPublisher` để gói event vào một envelope. Đây là sửa mã của Milestone 5 một cách có chủ ý, không phải phát sinh ngoài dự kiến.

**Redis và Kafka có vai khác nhau, không thay nhau được.** Redis pub/sub: việc nhẹ, cần ngay, mất cũng không sao (đổi màu ghế — client vào sau sẽ load lại seat map qua REST). Kafka: việc nặng, chậm, **không được mất** (gửi email, đối soát). Dùng Kafka để đổi màu ghế là thêm độ trễ vô ích; dùng Redis pub/sub để gửi email là mất email khi không có subscriber nào đang sống.

**Broadcast sau COMMIT, không phải trong transaction.** Nếu publish Redis ngay trong transaction rồi transaction rollback, mọi UI đang mở vừa nhận một sự thật không tồn tại. Dùng `TransactionSynchronizationManager.registerSynchronization` với `afterCommit`.

package com.cinebook.worker.support;

import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.context.DynamicPropertyRegistry;
import org.springframework.test.context.DynamicPropertySource;
import org.testcontainers.postgresql.PostgreSQLContainer;

/**
 * Container dung chung cho ca lop con — khoi dong mot lan cho ca lan chay test.
 * Cung mau voi AbstractIntegrationTest ben cinebook-api.
 *
 * Flyway bat lai o day: production worker KHONG migrate (api so huu schema), nhung
 * container test la DB trang nen phai co ai do dung schema len.
 */
@SpringBootTest(properties = "spring.flyway.enabled=true")
public abstract class AbstractWorkerTest {

    static final PostgreSQLContainer POSTGRES =
            new PostgreSQLContainer("postgres:18-alpine");

    static {
        POSTGRES.start();
    }

    @DynamicPropertySource
    static void datasource(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", POSTGRES::getJdbcUrl);
        registry.add("spring.datasource.username", POSTGRES::getUsername);
        registry.add("spring.datasource.password", POSTGRES::getPassword);
    }
}
```

package com.cinebook.worker;

import com.cinebook.payment.infra.ReconcilePaymentsUseCase;
import com.cinebook.shared.outbox.OutboxRelay;
import com.cinebook.worker.support.AbstractWorkerTest;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.ApplicationContext;
import org.springframework.core.env.Environment;
import org.springframework.web.bind.annotation.RestController;

import static org.assertj.core.api.Assertions.assertThat;

class WorkerWiringTest extends AbstractWorkerTest {

    @Autowired
    OutboxRelay relay;

    @Autowired
    ReconcilePaymentsUseCase reconcile;

    @Autowired
    Environment env;

    @Autowired
    ApplicationContext context;

    @Test
    void worker_chay_duoc_use_case_nghiep_vu_cua_api() {
        // Chua co gi de lam, nhung phai chay den noi tren DB that.
        assertThat(relay.relayBatch(10)).isZero();
        assertThat(reconcile.reconcile()).isZero();
    }

    /**
     * Khoa lai mot cai bay da kiem chung bang thuc nghiem: co HAI application.yml tren
     * classpath (mot cua worker, mot nam trong jar cua api), va Spring Boot chi doc mot.
     * File cua api bi bo qua HOAN TOAN, khong mot dong canh bao.
     *
     * Test nay ton tai de nguoi sau khong mat mot buoi chieu tu hoi vi sao property
     * minh khai o ben api lai khong co tac dung o worker.
     */
    @Test
    void worker_khong_thua_huong_cau_hinh_cua_api() {
        // cinebook.jwt.secret chi co trong application.yml cua api
        assertThat(env.getProperty("cinebook.jwt.secret")).isNull();
        // con cai worker tu khai thi phai co
        assertThat(env.getProperty("cinebook.payment.reconcile-after")).isEqualTo("15m");
    }

    @Test
    void worker_khong_nap_controller_nao_cua_api() {
        assertThat(context.getBeanNamesForAnnotation(RestController.class)).isEmpty();
    }
}

package com.cinebook.booking.infra;

import com.cinebook.shared.outbox.OutboxWriter;
import org.springframework.jdbc.core.namedparam.NamedParameterJdbcTemplate;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import java.util.Collections;
import java.util.List;
import java.util.UUID;

/**
 * Lop thu hai cua co che het han (spec muc 6.6).
 *
 * KHONG chiu trach nhiem ve tinh dung dan — lazy expiration trong HoldSeatsUseCase moi
 * la thu dam bao khong ai bi khoa ghe oan. Sweeper mua tinh KIP THOI: UI nguoi khac thay
 * ghe trong ra ma khong can ai thu giu. Test
 * khong_co_sweeper_thi_van_giu_duoc_ghe_da_het_han_cua_nguoi_khac giu lai su that do.
 */
@Component
public class SweepExpiredHoldsUseCase {

    private static final String SQL_RELEASE_SEATS = """
            UPDATE seat_hold
               SET status = 'EXPIRED', released_at = now(), release_reason = 'SWEPT'
             WHERE status = 'HELD'
               AND expires_at <= now()
            RETURNING seat_id::text
            """;

    private static final String SQL_EXPIRE_BOOKINGS = """
            UPDATE bookings
               SET status = 'EXPIRED', version = version + 1
             WHERE status = 'PENDING'
               AND hold_expires_at <= now()
            RETURNING id::text
            """;

    private final NamedParameterJdbcTemplate jdbc;
    private final OutboxWriter outbox;
    private final AuditLogger auditLogger;

    public SweepExpiredHoldsUseCase(NamedParameterJdbcTemplate jdbc, OutboxWriter outbox,
                                    AuditLogger auditLogger) {
        this.jdbc = jdbc;
        this.outbox = outbox;
        this.auditLogger = auditLogger;
    }

    @Transactional
    public int sweep() {
        List<String> gheDaNha = jdbc.query(SQL_RELEASE_SEATS,
                Collections.emptyMap(), (rs, n) -> rs.getString(1));

        List<String> donHetHan = jdbc.query(SQL_EXPIRE_BOOKINGS,
                Collections.emptyMap(), (rs, n) -> rs.getString(1));

        for (String bookingId : donHetHan) {
            UUID id = UUID.fromString(bookingId);
            // Cung transaction voi hai cau UPDATE tren — khong co khe ho "da het han
            // nhung khong ai duoc bao".
            outbox.write("BOOKING", id, "BookingExpired",
                    "{\"bookingId\":\"" + bookingId + "\"}");
            auditLogger.record("BOOKING", id, "EXPIRED",
                    AuditLogger.ActorType.SYSTEM, null, "{\"by\":\"SWEEPER\"}");
        }

        return gheDaNha.size();
    }
}
```

**Chú ý thứ tự:** nhả ghế trước, đóng đơn sau. Ngược lại thì trong khoảnh khắc giữa hai câu sẽ tồn tại đơn `EXPIRED` mà ghế vẫn `HELD` — một trạng thái không hợp lệ mà bất kỳ ai đọc DB lúc đó cũng thấy. Cùng transaction nên không ai thấy thật, nhưng thứ tự đúng vẫn rẻ hơn việc phải giải thích.

**Hai điều phát hiện khi làm bước này, đều đã sửa vào code:**

1. **Scheduler chạy thật trong test.** `@EnableScheduling` trên `WorkerApplication` khiến `SweeperJob` chạy ngay lúc context khởi động, chiếm khoá và giữ tối thiểu 10 giây theo `lockAtLeastFor` — nên test không bao giờ giữ được khoá để kiểm tra điều nó muốn kiểm tra. Tách `@EnableScheduling` sang `SchedulingConfig` mang `@Profile("!test")`, và `AbstractWorkerTest` khai `@ActiveProfiles("test")`. Aspect của `@EnableSchedulerLock` độc lập với `@EnableScheduling` nên test vẫn gọi thẳng vào job qua proxy và khoá vẫn có hiệu lực.

2. **Bẫy múi giờ làm cả hai test xanh vì lý do sai.** Cột `lock_until` kiểu `timestamp` **không mang múi giờ**; ShedLock với `usingDbTime()` ghi vào đó theo **UTC**, còn `now()` của Postgres trả về giờ phiên (+07). Câu dọn dẹp `UPDATE shedlock SET lock_until = now() - interval '1 minute'` do đó đẩy `lock_until` lên **bảy tiếng trong tương lai**, khoá trông như luôn bị giữ, và mọi khẳng định phía sau đều vô nghĩa. Quan sát được bằng cách in cả hai cột: `lock_until = 00:51:21` trong khi `locked_at = 17:52:21` của cùng một lần chạy. Sửa thành `(now() AT TIME ZONE 'UTC') - interval '1 minute'`.

Cũng vì bước này mà test thứ nhất được viết lại: khẳng định "khoá vẫn bị giữ sau khi gọi job" **không phân biệt được gì** (điều đó đúng cả khi job vừa chạy xong, do `lockAtLeastFor`). Test đúng phải có cả hai nửa — khoá tự do thì job chạy **và** chiếm khoá; khoá bị giữ thì dòng khoá không đổi một chút nào.

```java
package com.cinebook.worker.publish;

import com.cinebook.shared.outbox.EventPublisher;
import com.cinebook.shared.outbox.OutboxMessage;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.stereotype.Component;

@Component
public class KafkaEventPublisher implements EventPublisher {

    private final KafkaTemplate<String, String> kafka;

    public KafkaEventPublisher(KafkaTemplate<String, String> kafka) {
        this.kafka = kafka;
    }

    @Override
    public void publish(OutboxMessage message) {
        String envelope = """
                {"eventId":%d,"eventType":"%s","aggregateType":"%s","aggregateId":"%s","payload":%s}
                """.formatted(message.id(), message.eventType(), message.aggregateType(),
                message.aggregateId(), message.payload());

        // Key la aggregateId: moi event cua cung mot don vao cung mot partition, nen thu tu
        // trong pham vi mot don duoc giu nguyen. Khong can thu tu toan cuc.
        // .get() de chuyen loi gui thanh exception dong bo — OutboxRelay dua vao exception
        // de biet ma KHONG danh dau published_at.
        kafka.send(topicCho(message.aggregateType()), message.aggregateId().toString(), envelope)
                .join();
    }

    private String topicCho(String aggregateType) {
        return switch (aggregateType) {
            case "PAYMENT" -> "payment.events";
            default -> "booking.events";
        };
    }
}
```

- [ ] **Step 2: Publish sau COMMIT**

```java
    public void seatsChanged(UUID showtimeId, String payload) {
        if (!TransactionSynchronizationManager.isSynchronizationActive()) {
            doPublish(showtimeId, payload);
            return;
        }
        TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
            @Override
            public void afterCommit() {
                doPublish(showtimeId, payload);
            }
        });
    }

    private void doPublish(UUID showtimeId, String payload) {
        try {
            redis.convertAndSend("seatmap:" + showtimeId, payload);
        } catch (RuntimeException e) {
            // Redis chet KHONG duoc lam hong giao dich giu ghe. Mat realtime thi UI cua
            // nguoi khac cham mot nhip; nem exception o day thi khong ai mua duoc ve.
            log.warn("Khong publish duoc thay doi seat map cho {}", showtimeId, e);
        }
    }
```

Hai chi tiết đều quan trọng: **`afterCommit`** để không bao giờ phát đi một sự thật bị rollback, và **nuốt exception** để Redis chết không kéo theo đường bán vé.
