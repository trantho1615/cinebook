# Milestone 7 — UI tối giản

**Goal:** Một giao diện đủ để **quay được video demo**: chọn suất chiếu → thấy sơ đồ ghế đổi màu realtime khi người khác giữ ghế → giữ ghế với đồng hồ đếm ngược → thanh toán → vé được xác nhận. Không hơn.

**Architecture:** HTML + CSS + JavaScript thuần, **không có bước build**, phục vụ thẳng từ `cinebook-api` dưới dạng static resource. Không framework, không npm, không bundler. UI gọi đúng những REST endpoint đã có từ Milestone 2-5 và nghe kênh STOMP đã dựng ở Milestone 6.

**Tech Stack:** HTML5, CSS thuần, JavaScript ES2022 (module), WebSocket + STOMP frames viết tay.

**Spec:** `docs/specs/2026-08-11-cinebook-core-design.md` — dòng 8 của lộ trình mục 10 ("UI tối giản: seat map realtime + trang thanh toán → quay được video demo").

## Bằng chứng đã thu thập trước khi viết plan

Chạy `cinebook-api` thật với profile `demo` rồi gọi từng endpoint mà UI sẽ dùng, thay vì suy hình dạng JSON từ code:

| Endpoint | Hình dạng thật |
|---|---|
| `POST /auth/login` | `{"accessToken":"eyJ...","refreshToken":"avV...","expiresInSeconds":900}` |
| `GET /showtimes?city=` | mảng `{showtimeId, startAt, movieId, movieTitle, cinemaId, cinemaName, district, roomId, roomName, basePrice}` |
| `GET /showtimes/{id}/seats` | mảng `{seatId, rowLabel, seatNumber, label, seatType, price, status}`; `status` quan sát được: `AVAILABLE`, `HELD` |
| `POST /showtimes/{id}/holds` | 201 → `{bookingId, code, status, totalAmount, holdExpiresAt, seats:["A1","A2"]}` |
| `POST /bookings/{id}/payments` | 201 → `{paymentId, redirectUrl, amount}` |

Hai phát hiện khác, cả hai đều thành việc phải làm trong milestone này:

| Quan sát | Ý nghĩa |
|---|---|

## Quyết định thiết kế cần hiểu trước khi code

**Không framework, không bước build.** UI này tồn tại để quay demo và để người đọc CV bấm thử, không phải để cạnh tranh với một sản phẩm thật. Thêm React + Vite là thêm `node_modules`, thêm một pipeline build vào CI, và thêm một thứ nữa phải bảo trì — đổi lại không chứng minh thêm được điều gì về phần backend, vốn là toàn bộ điểm của dự án. Ba trang HTML tĩnh thì `docker compose up` là chạy được.

**Phục vụ từ chính `cinebook-api`.** Mục 2.2 của spec liệt kê `web/` như một thư mục riêng, nhưng đặt file tĩnh vào `cinebook-api/src/main/resources/static/` bỏ được CORS, bỏ được một tiến trình phải chạy khi demo, và UI thì nhỏ. Đây là chỗ **cố ý lệch khỏi spec** — ghi lại để sau này không ai tưởng là quên.

**Token giữ trong `sessionStorage`, không phải `localStorage`.** Đóng tab là mất token. Cả hai đều đọc được bằng JavaScript nên đều không chống được XSS; `sessionStorage` chỉ thu hẹp cửa sổ thời gian. Cách đúng cho sản phẩm thật là refresh token trong cookie `HttpOnly` + `SameSite`, và đó là việc của một milestone khác — ghi vào bảng "cố ý chưa làm" chứ không lặng lẽ bỏ qua.

**Viết STOMP client tay, không nhúng thư viện.** Frame STOMP là text thuần: một dòng lệnh, các header `key:value`, một dòng trống, body, kết thúc bằng byte `NUL`. Một client chỉ cần `CONNECT` và `SUBSCRIBE` gọn trong khoảng 40 dòng, và hiểu được nó có giá trị hơn nhiều so với việc kéo về 30 KB minified. **Nếu tới lúc code mà frame parsing lằng nhằng hơn dự tính, dừng lại và nhúng `stomp.umd.min.js` vào `static/vendor/`** — đừng đổ thêm thời gian vào chỗ không phải trọng tâm của dự án.

**UI đọc lại sơ đồ ghế khi nhận bản tin, không tin bản tin làm nguồn sự thật.** Bản tin realtime mang danh sách ghế đổi trạng thái, nhưng client vào giữa chừng hoặc mất kết nối vài giây sẽ có bức tranh sai nếu chỉ dựa vào nó. Nguồn sự thật vẫn là Postgres qua `GET /showtimes/{id}/seats`. Bản tin dùng để **biết khi nào cần đọc lại**, và để tô ngay những ghế nó nhắc tới cho phản hồi tức thì.

**Đường thanh toán trong demo cần một cổng giả.** `MockPaymentGateway` trả `redirectUrl` trỏ tới `https://sandbox.example.com` — không tồn tại. Trình duyệt **không thể** tự gọi webhook vì webhook yêu cầu chữ ký HMAC, mà bí mật ký thì không được phép có mặt trong JavaScript. Nên demo cần một endpoint chỉ bật ở profile `demo`: nó dựng payload, tự ký bằng bí mật phía server, rồi đi đúng đường mà webhook thật đi. Test phải khẳng định endpoint này **không tồn tại** khi không có profile `demo`.

- [ ] **Step 1: Lớp bọc gọi API**

`api.js` gánh ba việc, và chỉ ba việc:

```js
const KEY = 'cinebook.token';

export function token() {
  return sessionStorage.getItem(KEY);
}

export async function login(email, password) {
  const res = await post('/auth/login', { email, password });
  sessionStorage.setItem(KEY, res.accessToken);
  return res;
}

async function goi(method, path, body) {
  const res = await fetch(path, {
    method,
    headers: {
      'Content-Type': 'application/json',
      ...(token() ? { Authorization: `Bearer ${token()}` } : {}),
    },
    body: body === undefined ? undefined : JSON.stringify(body),
  });

  if (res.status === 401) {
    // Access token song 15 phut. Het han giua chung la chuyen binh thuong, khong phai loi.
    sessionStorage.removeItem(KEY);
    location.href = '/index.html';
    throw new Error('Phien dang nhap da het han');
  }
  if (!res.ok) {
    // ApiError cua backend: {code, message}. Hien message cho nguoi dung thay vi
    // "Something went wrong".
    const loi = await res.json().catch(() => ({ message: res.statusText }));
    throw Object.assign(new Error(loi.message), { code: loi.code, status: res.status });
  }
  return res.status === 204 ? null : res.json();
}
```

Backend trả `ApiError {code, message}` cho mọi lỗi nghiệp vụ từ Milestone 2 trở đi — UI hiển thị thẳng `message`, và dùng `code` khi cần phân biệt (`SEATS_UNAVAILABLE`, `HOLD_EXPIRED`).

## Task 3: Sơ đồ ghế realtime

**Files:**

- [ ] **Step 1: STOMP client tối giản**

Frame STOMP là text thuần, kết thúc bằng byte `NUL` (` `):

```
CONNECT
accept-version:1.2
host:localhost

^@
```

Client chỉ cần `CONNECT`, `SUBSCRIBE`, và đọc `MESSAGE`:

```js
export function ketNoi(url, dich, khiCoTin) {
  const ws = new WebSocket(url);

  ws.onopen = () => guiFrame(ws, 'CONNECT', { 'accept-version': '1.2', host: location.hostname });
  ws.onmessage = (e) => {
    const { lenh, headers, body } = docFrame(e.data);
    if (lenh === 'CONNECTED') {
      guiFrame(ws, 'SUBSCRIBE', { id: 'sub-0', destination: dich });
    } else if (lenh === 'MESSAGE') {
      khiCoTin(JSON.parse(body));
    }
  };
  return ws;
}
```

**Nếu bước này ngốn quá một tiếng, dừng lại và nhúng `stomp.umd.min.js` vào `static/vendor/`.** Nó không phải trọng tâm của dự án.

- [ ] **Step 2: Vẽ sơ đồ ghế**

`GET /showtimes/{id}/seats` trả mảng phẳng có `rowLabel` và `seatNumber` — nhóm theo `rowLabel` để dựng lưới. Bốn trạng thái hiển thị: trống, người khác giữ, đã bán, mình đang chọn.

- [ ] **Step 3: Nối realtime**

Subscribe `/topic/showtimes/{id}`. Bản tin có dạng `{"showtimeId":"...","status":"HELD","seats":["A1","A2"]}` (Milestone 6).

Khi nhận: tô ngay những ghế được nhắc tới cho phản hồi tức thì, **rồi gọi lại** `GET /showtimes/{id}/seats` để đồng bộ với nguồn sự thật. Client vào giữa chừng hoặc mất kết nối vài giây sẽ sai nếu chỉ nghe bản tin.

- [ ] **Step 4: Giữ ghế và đếm ngược**

`POST /showtimes/{id}/holds` trả `holdExpiresAt`. Đếm ngược từ đó, hết giờ thì quay lại sơ đồ và tải lại.

Xử lý riêng `409 SEATS_UNAVAILABLE`: hiện đúng danh sách ghế bị mất trong `message` và tải lại sơ đồ — đây là tình huống *thường gặp* trong một buổi bán vé đông, không phải lỗi hiếm.

- [ ] **Step 5: Kiểm tra bằng tay — đây là cảnh chính của video demo**

Mở hai cửa sổ trình duyệt cạnh nhau, cùng một suất chiếu, hai tài khoản khác nhau:

1. Cửa sổ A giữ ghế A1, A2 → cửa sổ B **thấy hai ghế đổi màu ngay**, không cần tải lại.
2. Đợi hold hết hạn (hoặc đẩy `expires_at` về quá khứ bằng SQL) → sweeper trong worker nhả ghế → **cả hai cửa sổ thấy ghế trống ra**. Đây là chỗ chứng minh worker và UI gặp nhau qua Redis pub/sub.

- [ ] **Step 5b: Lam moi phien am tham**

Phat hien khi chay that: mo so do ghe khoang hai muoi phut roi bam "Giu ghe" thi bi da ve
trang dang nhap. Access token song 15 phut, con mot trang so do ghe thi mo lau hon the —
day la chuyen thuong chu khong phai truong hop hiem.

`api.js` gap 401 thi goi `/auth/refresh` roi thu lai dung mot lan. **Cai bay o day:** refresh
token cua Milestone 2 xoay vong va co phat hien tai su dung — dung mot token hai lan bi coi
la dau hieu bi danh cap va **ca ho token bi thu hoi**. Trang so do ghe ban ra nhieu request
song song, nen hai request cung dinh 401 se cung goi `/auth/refresh` voi cung mot token va
tu khoa chinh minh ra ngoai. Gom moi lan lam moi vao mot promise duy nhat.

Da kiem chung ca hai nua: hai request song song voi access token hong deu chay xong va
refresh token xoay dung mot lan; con goi `/auth/refresh` hai lan voi cung mot token thi lan
thu hai tra **401 `INVALID_REFRESH_TOKEN`** — tuc bo gom kia la thu chiu luc, khong phai
trang tri.

- [ ] **Step 2: Cổng thanh toán giả**

```java
@RestController
@Profile("demo")
public class DemoGatewayController {

    /**
     * Trinh duyet KHONG the tu goi webhook: webhook doi chu ky HMAC, va bi mat ky thi
     * khong duoc phep co mat trong JavaScript. Endpoint nay dung payload, tu ky phia
     * server, roi di DUNG duong ma webhook that di — khong co nhanh logic thu hai.
     *
     * @Profile("demo") la thu ngan no khoi moi truong that. DemoGatewayTest khang dinh
     * dieu do bang mot lop test khong bat profile demo.
     */
    @PostMapping("/demo/payments/{paymentId}/{ketQua}")
    public ResponseEntity<Void> hoanTat(@PathVariable UUID paymentId, @PathVariable String ketQua) {
        String body = """
                {"eventId":"demo-%s-%s","paymentId":"%s","status":"%s","providerTxnId":"MOCK-DEMO"}"""
                .formatted(paymentId, ketQua, paymentId,
                        "succeed".equals(ketQua) ? "SUCCEEDED" : "FAILED");

        recordWebhook.record("MOCK", body, signature.sign(body), true);
        processPayment.process(body);
        return ResponseEntity.accepted().build();
    }
}
```

Nhớ mở `/demo/**` trong `SecurityConfig` — nhưng **chỉ khi profile demo bật**. Cách gọn nhất: một `SecurityFilterChain` riêng mang `@Profile("demo")` với `@Order` cao hơn, khớp `/demo/**`. Không thêm dòng nào vào chuỗi chính, để không có gì phải nhớ gỡ ra trước khi deploy.

- [ ] **Step 3: Trang thanh toán**

`checkout.html?bookingId=...`: hiện mã đơn, phim, ghế, tổng tiền, đồng hồ đếm ngược còn lại của hold. Nút "Thanh toán" gọi `POST /bookings/{id}/payments`, rồi hiện `redirectUrl` như một cổng thật sẽ làm, kèm hai nút demo: **Giả lập thành công** / **Giả lập thất bại** → gọi `/demo/payments/{paymentId}/succeed|fail`.

Sau đó `GET /bookings/{id}` để hiện kết quả: `CONFIRMED` kèm mã vé, hoặc thông báo thất bại và ghế đã được nhả.

- [ ] **Step 4: Kiểm tra bằng tay — trọn vòng**

Giữ ghế → thanh toán thành công → vé `CONFIRMED`, và cửa sổ thứ hai thấy ghế chuyển sang "đã bán". Rồi lặp lại với "Giả lập thất bại" → ghế được nhả, sơ đồ của cả hai cửa sổ cập nhật.

**Ba lần viết lại `DemoGatewayAbsentTest` mới có được một test thật sự phân biệt được.** Bản đầu gọi vô danh và chấp nhận 401 — nhưng gỡ `@Profile` ra thì người lạ vẫn nhận 401, test vẫn xanh. Bản hai gọi kèm token nhưng dùng `paymentId` ngẫu nhiên — lời gọi ngã vì dữ liệu không tồn tại chứ không phải vì endpoint vắng mặt, nên "không phải 2xx" vẫn đúng cả khi endpoint có thật. Bản ba khẳng định vào **hậu quả**: dùng một giao dịch có thật của chính người gọi và đòi đơn phải còn `PENDING`. Gỡ `@Profile` ra thì test đỏ với `expected: "PENDING"`.

Đáng ghi thêm: đường không có handler trong ứng dụng này trả **401 chứ không phải 404**, vì nhánh chuyển sang `/error` không còn security context và `anyRequest().authenticated()` áp lên cả nó. Đo được bằng thực nghiệm — cùng token đó gọi `GET /bookings` trả 200.

**Một lỗi UI mà chỉ chạy thật mới thấy:** bấm "Giả lập thành công" hiện `Unexpected end of JSON input`. Cổng giả trả **200 với thân rỗng** (`ResponseEntity<Void>`), còn `api.js` chỉ coi 204 là không có nội dung nên vẫn gọi `res.json()`. Thanh toán đã đi qua (`CONFIRMED / SUCCEEDED` trong DB) — chỉ có UI không đọc nổi. Sửa: đọc `text()` rồi mới parse.
